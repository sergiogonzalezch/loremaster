## 4. Fixes y mejoras aplicados en 2026-05-18

### 4.1 Logging backend (`fix(logging)` — commit `0c1d117`)

**Problema 1:** `configure_logging()` se llama en `main.py`, que uvicorn re-importa en cada `--reload`. Sin `handlers.clear()`, cada reload añadía un `StreamHandler` adicional al root logger, duplicando cada línea de log N veces.

**Solución:** `root_logger.handlers.clear()` antes de `addHandler` en `core/logging.py`.

**Problema 2:** `uvicorn.access` tiene `propagate = False` en el dictConfig que uvicorn aplica al arrancar, por lo que los logs de requests (`GET /api/v1/... 200`) no llegaban al root handler.

**Solución:** En `lifespan.py`, tras el `yield` (después de que uvicorn haya aplicado su dictConfig), se limpian los handlers de `uvicorn.access` y se activa `propagate = True`.

### 4.2 Dark theme SourcesModal y Swagger CSP (`fix(ui)` — commit `436cb51`)

- **SourcesModal accordion:** Bootstrap 5 usa `var(--bs-accordion-bg)` (blanco) incluso dentro de un modal oscuro. Se añadieron overrides `.modal .accordion-*` en `index.css` que fuerzan las variables CSS del tema (`--lm-raised`, `--lm-surface`, `--lm-text`, `--lm-border`).
- **Score badge:** Reemplazado `bg-light text-secondary` por inline styles con `--lm-accent-glow`, `--lm-accent`, `--lm-border-accent`.
- **Textarea en modales:** `background-color: var(--lm-raised) !important` explícito (el shorthand `background` perdía contra el `background-color` de Bootstrap).
- **CSP Swagger:** `SecurityHeadersMiddleware` ahora devuelve la response sin añadir CSP cuando la ruta empieza por `/docs`, `/redoc` u `/openapi.json`.

### 4.3 Launchers — espera de backend (`feat(launcher)` — commit `32a1432`)

`dev.ps1` y `loremaster.sh` arrancaban backend y frontend simultáneamente. El frontend cargaba antes de que las migraciones y los health checks del backend estuvieran completos.

**Solución:** Bucle de polling sobre `GET http://localhost:8000/health` entre el arranque del backend y el del frontend:
- **`dev.ps1`:** `Invoke-WebRequest` cada 2 s, timeout 120 s, con indicador visual de puntos.
- **`loremaster.sh`:** `until curl -sf http://localhost:8000/health`, sin límite (el backend siempre arranca).

El endpoint `/health` responde solo tras el `yield` del lifespan (migraciones + pings de Qdrant/Ollama completados), por lo que es la señal de readiness correcta.

## 5. Refactors estructurales backend

Auditoría completa de `core/`, `api/routes/`, `api/middlewares/`, `domain/`, `engine/`, `services/`, `models/`. Se identificaron y resolvieron 5 puntos de mejora.

### 5.1 Extract RAG query service (`refactor(core)` — commit `4fa6e64`)

**Problema:** `rag_query.py` contenía validación de entrada, invocación del pipeline y validación de salida directamente en el route handler.

**Solución:** `services/collection/rag_query_service.py` con `execute_rag_query(collection_id, query) → (answer, sources_count, source_doc_ids)`. El route queda exclusivamente como capa HTTP: strips la query, llama al servicio, mapea excepciones a status codes y registra eventos de moderación.

### 5.2 DuplicateNameError unificado (`refactor(core)` — commit `4fa6e64`)

`DuplicateEntityNameError` y `DuplicateCollectionNameError` eran la misma abstracción con nombres distintos. Colapsados en `DuplicateNameError(name, message)`. El mensaje de contexto se pasa en el punto de raise (donde está la información de dominio); los routes capturan un único tipo → 409.

### 5.3 bulk_delete_items helper (`refactor(core)` — commit `4fa6e64`)

El patrón `for item in items: with contextlib.suppress(Exception): delete_fn(session, item)` estaba triplicado en `collections.py`, `documents.py` y `entities.py`. Extraído a `core/database/utils.bulk_delete_items(session, items, delete_fn)`. Los tres routes pasaron de 6 líneas a 2.

### 5.4 Eliminar `except Exception` genéricos (`refactor(core)` — commit `4fa6e64`)

`image_generation.py` tenía bloques `except Exception → logger + 500` en 5 endpoints. FastAPI/Starlette maneja excepciones no capturadas como 500 y las registra vía `ServerErrorMiddleware`, por lo que los catches eran redundantes y ocultaban tipos de error reales.

### 5.5 Split image_generation_service (`refactor(image-service)` — commit `5aa8fa0`)

`image_generation_service.py` (634 líneas) mezclaba backends (mock/ComfyUI), persistencia DB y la API pública.

**Solución:**
- `services/image/_backends.py` (130 líneas): funciones puras sin sesión. `_generate_mock_images` y `_generate_comfyui_images` devuelven `list[_ImageData]`. No acceden a la BD.
- `services/image/image_generation_service.py` (~290 líneas): crea el `ImageGeneration` DB record, llama al backend, crea los `ImageRecord` en un loop uniforme, `db_commit`. El flujo es idéntico para ambos backends.
