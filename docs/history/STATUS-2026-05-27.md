## 3. Deliverables Semana 9

### 3.1 Containerización backend (`b3cd6c5`, `0de3b70`)

**`backend/Dockerfile`** — multi-stage:

- **Stage builder:** `python:3.12-slim`, instala deps con `--prefix=/install`, pre-descarga el embedding model `paraphrase-multilingual-MiniLM-L12-v2` (~90 MB) para eliminar el cold-start en el primer deploy. Instala torch CPU-only (`--index-url https://download.pytorch.org/whl/cpu`) — reducción de ~6.6 GB a ~2.6 GB.
- **Stage runtime:** usuario no-root `loremaster` (UID 1000), copia deps y cache del modelo, `CMD uvicorn app.main:app --host 0.0.0.0 --port 8000`.
- **`backend/.dockerignore`:** excluye `venv/`, `*.db`, `media/`, `tests/`, `evaluations/`, `__pycache__/`, `.env`.

### 3.2 Containerización frontend (`b61c93c`)

**`frontend/Dockerfile`** — multi-stage:

- **Stage builder:** `node:20-alpine`, `npm ci`, `npm run build` → dist/
- **Stage runtime:** `nginx:alpine` (~63 MB total), copia `nginx.conf` y el bundle compilado.
- **`frontend/.dockerignore`:** excluye `node_modules/`, `dist/`, `src/test/`.

**`frontend/nginx.conf`** — proxy inverso con 4 bloques:
- `location /` → SPA (`try_files $uri $uri/ /index.html`)
- `location /health` → backend `:8000/health` (FastAPI root — no bajo `/api/v1/`)
- `location /api/` → backend `:8000/api/` con timeouts LLM (120s)
- `location /media/` → Floci interno `:4566/loremaster-media/`

> **Fix crítico:** el endpoint `/health` está en la raíz de FastAPI, no bajo `/api/v1/`. Sin el bloque explícito, `curl http://localhost/health` retornaba `index.html` (SPA fallback). Descubierto al verificar el stack.

### 3.3 Stack de demo — `docker-compose.prod.yml`

6 servicios en red Docker interna (`loremaster`):

| Servicio | Container | Puerto host | Notas |

### 3.4 CORS eliminado

`STORAGE_BASE_URL=http://localhost/media` — Nginx proxea `/media/` → Floci interno. El frontend usa `VITE_API_BASE_URL=/api/v1` (ruta relativa). Toda la comunicación pasa por el mismo origen (`:80`). Sin necesidad de CORS entre frontend ↔ backend ↔ storage.

### 3.8 Seguridad — path traversal (`3a5818b`)

**Finding del security review externo** (Semana 9): `delete_image_service()` borraba ficheros sin validar que `storage_path` apuntase dentro de `media_root`.

```python
# Antes
full_path = Path(settings.media_root) / record.storage_path
full_path.unlink()

# Después — alineado con deletion_service.py, profile_service.py, core/storage/__init__.py
media_root_resolved = Path(settings.media_root).resolve()
full_path = (media_root_resolved / record.storage_path).resolve()
if full_path.is_relative_to(media_root_resolved):
    with suppress(FileNotFoundError, OSError):
        full_path.unlink()
else:
    logger.warning("Attempted to delete file outside media_root: %s", record.storage_path)
```

Severidad: Media (no explotable directamente — `storage_path` se construye desde UUIDs via `build_generation_path()`). Pero defensa en profundidad: un compromiso de DB no puede escalar a borrado de ficheros arbitrarios.

El patrón ya existía en 4 lugares. `delete_image_service` era el único que no lo aplicaba.

### 3.9 Herramientas de operación

```bash
make prod-up             # Levanta el stack completo
make prod-down           # Baja todo
make prod-rebuild        # Reconstruye backend + frontend
make prod-rebuild-api    # Solo backend (cambios Python)
make prod-rebuild-fe     # Solo frontend (cambios React/CSS)
make make-admin USER=<u> # Promueve usuario a admin en stack Docker
```

`make make-admin` usa guard portable de Make: `$(if $(USER),,$(error ...))` en lugar de `ifndef`/`endif` — funciona en cualquier versión de Make.

## 4. Fixes operacionales

| Problema | Causa | Fix |
|---|---|---|
| `curl http://localhost/health` → HTML | FastAPI `/health` no está bajo `/api/v1/`; Nginx no tenía location para esa ruta | `location /health { proxy_pass ... }` en nginx.conf |
| Imágenes no cargan en producción | 4 filas en `image_records` con `image_url=http://localhost:4566/...` (URL directa Floci) | SQL `UPDATE image_records SET image_url = NULL WHERE image_url LIKE '%localhost:4566%'`; backend recomputa via Nginx |
| `Optimize-VHD` permission error | PowerShell no elevado | Requiere: cerrar Docker Desktop → `wsl --shutdown` → PowerShell como Administrador |
