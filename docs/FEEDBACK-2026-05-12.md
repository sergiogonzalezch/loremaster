## 2. Issues de ruff (ruleset extendido)

Con `--select ALL` se encontraron **630 issues** de los cuales 151 son auto-reparables. Los bloques más relevantes:

### 2.1 FAST002 + B008 — Dependencias FastAPI sin `Annotated` (223 ocurrencias) — ⏳ Pendiente

**Qué es:** FastAPI recomienda desde v0.95 usar `Annotated` para declarar dependencias en lugar de valores por defecto. El patrón actual funciona igual pero mezcla la firma del endpoint con la inyección de dependencias.

```python
# Patrón actual (funciona, pero mezcla firma + DI)
def create_entity(
    session: Session = Depends(get_session),
    user: User = Depends(get_current_user),
):

# Patrón moderno (firma limpia, DI explícita)
def create_entity(
    session: Annotated[Session, Depends(get_session)],
    user: Annotated[User, Depends(get_current_user)],
):
```

**Impacto:** Cosmético. No corregir en este momento es razonable — es un refactor masivo (~20 archivos de rutas) sin ganancia funcional inmediata. Anotar como deuda técnica.

---

### 2.2 UP045 — `Optional[X]` → `X | None` (79 ocurrencias) — ✅ Resuelto en `c947f99`

**Qué es:** La sintaxis PEP 604 (`X | None`) está disponible desde Python 3.10+. `Optional[X]` es equivalente pero más verboso.

```python
# Actual
from typing import Optional
_jwks_cache: Optional[dict] = None

# Moderno
_jwks_cache: dict | None = None
```

**Impacto:** Cosmético. Auto-reparable con `ruff --fix`. Bajo riesgo.

---

### 2.3 B904 — `raise` sin `from` en bloques `except` (56 ocurrencias) — ✅ Resuelto en `e62c0db`

**Qué es:** Al relanzar una excepción dentro de un `except`, perder la cadena de causas dificulta el diagnóstico en producción.

```python
# Actual (pierde la causa original)
except JWTError:
    raise HTTPException(status_code=401, detail="Token inválido")

# Correcto
except JWTError as e:
    raise HTTPException(status_code=401, detail="Token inválido") from e
```

**Archivos con mayor concentración:** `auth_clerk.py`, `documents.py`, `entities/content.py`, `collections.py`.

**Recomendación:** Corregir en los módulos críticos de auth y documentos. En los routers REST es menos urgente.

---

### 2.4 PLC0415 — Imports fuera del top-level (10 ocurrencias) — ✅ Parcialmente resuelto en `2b16b9f` / ⏳ Resto pendiente

**Qué es:** Imports dentro de funciones o métodos en lugar del nivel superior del módulo. En algunos casos es intencional (para evitar imports circulares), pero en otros es residual.

**Ejemplo detectado:** `import re` dentro de `upload_profile_image` en `profile_service.py` (añadido en el fix C-5). Este `re` podría subir al top del archivo.

**Recomendación:** Revisar los 10 casos. Si el import es circular, documentarlo con un comentario; si no, moverlo arriba.

### 2.5 PLW0603 — `global` en `auth_clerk.py` (3 ocurrencias) — ⏳ Pendiente

**Qué es:** La caché de JWKS usa `global _jwks_cache` + `threading.Lock` a nivel módulo.

```python
# Actual
_jwks_cache: Optional[dict] = None
_jwks_cache_time: float = 0.0
_jwks_lock = threading.Lock()

def get_jwks() -> dict:
    global _jwks_cache, _jwks_cache_time
    ...
```

**Problema adicional:** `httpx.get()` es **síncrono** en un handler que se ejecuta en el event loop de FastAPI. Si Clerk tarda en responder, bloquea el worker completo.

**Mejora sugerida (dos pasos):**
1. Encapsular caché en una pequeña clase o usar `functools.lru_cache` con TTL manual.
2. Usar `httpx.AsyncClient` (o `anyio.to_thread.run_sync`) para la llamada HTTP.

### 2.6 S110 — `except Exception: pass` en `rate_limit.py` (3 ocurrencias) — ✅ Resuelto en `2b16b9f`

**Qué es:** `_extract_user_from_token` silencia cualquier excepción con `pass`. Funciona, pero `Exception` es muy amplio.

```python
# Actual
try:
    ...
    return payload.get("sub")
except Exception:
    pass
return None

# Más preciso
try:
    ...
    return payload.get("sub")
except (ValueError, KeyError, UnicodeDecodeError, binascii.Error):
    return None
```

**Impacto:** Bajo. El método ya tiene un comportamiento seguro por defecto (`return None`). La mejora es legibilidad.

---

### 2.7 TRY400 — `logger.error` en vez de `logger.exception` (12 ocurrencias) — ✅ Resuelto en `e62c0db`

**Qué es:** Dentro de bloques `except`, `logger.exception()` incluye automáticamente el traceback. `logger.error()` sin `exc_info=True` lo omite.

```python
# Actual (pierde el traceback)
except SQLAlchemyError as e:
    logger.error("DB commit failed during %s: %s", operation, e)

# Correcto (incluye traceback)
except SQLAlchemyError:
    logger.exception("DB commit failed during %s", operation)
```

**Archivos afectados:** `core/database/utils.py` (el más claro), `documents_service.py`, varios servicios.

**Recomendación:** Aplicar en `db_commit()` y en los servicios donde el traceback tenga valor diagnóstico real.

---

### 2.8 LOG015 — Root logger en `documents.py` — ✅ Resuelto en `2b16b9f`

**Qué es:** Una llamada a `logging.exception(...)` directamente en vez de usar el logger nombrado del módulo.

```python
# Actual (usa root logger)
logging.exception(...)

# Correcto
logger = logging.getLogger(__name__)
logger.exception(...)
```

`documents.py` ya define `logger = logging.getLogger(__name__)` — es una inconsistencia puntual.

---

### 2.9 PTH123 / PTH107 / PTH118 — `open()` y `os.*` en vez de `pathlib` (5 ocurrencias) — ✅ Resuelto en `2b16b9f`

**Qué es:** El proyecto usa `pathlib.Path` correctamente en la mayoría del código de storage, pero quedan algunos usos de la API antigua:

- `open(path, "wb")` en `core/storage/__init__.py` (línea 26) → `path.write_bytes(content)`
- `os.remove(...)` en algún servicio → `Path(...).unlink()`
- `os.path.join(...)` → `Path(...) / ...`

**Impacto:** Cosmético. Coherencia con el estilo dominante del proyecto.

## 3. Issues arquitectónicos (fuera de ruff)

### 3.1 `services/__init__.py` — barrel sin consumidores

El archivo re-exporta 29 símbolos de todos los dominios de servicios. Sin embargo, **ningún router lo usa**: todos importan directamente del subpackage (`from app.services.entity import ...`). El barrel añade una capa de indirección sin aportar ningún valor.

**Opciones:**
- Eliminarlo (opción preferida si los imports directos son el patrón establecido).
- Documentar que es solo para facilitar imports en tests externos (si ese es el caso).

---

### 3.2 `build_storage_path` — join incorrecto

```python
# core/storage/__init__.py, línea 10
def build_storage_path(*parts: str) -> Path:
    return Path(settings.media_root) / "/".join(parts)
```

`"/".join(parts)` genera un string con barras, pero en Windows `Path("root") / "a/b/c"` funciona distinto que `Path("root") / "a" / "b" / "c"`. El uso correcto es:

```python
return Path(settings.media_root).joinpath(*parts)
```

Funciona en todos los OS y es la API idiomática de pathlib.

---

### 3.3 `build_storage_url` — posible doble barra

```python
# core/storage/__init__.py, línea 36
return f"{settings.storage_base_url}/{relative_path}"
```

Si `storage_base_url` termina en `/`, la URL resultante tiene `//`. Solución:

```python
return f"{settings.storage_base_url.rstrip('/')}/{relative_path}"
```

---

### 3.4 `get_active_by_id` — acoplamiento a `collection_id`

La función en `core/database/utils.py` asume que el modelo tiene `collection_id`, lo que la hace inutilizable para modelos que no pertenecen a una colección (ej. `User`, `ModerationLog`). Es una utility que creció para un caso específico.

No es urgente, pero si se necesita una utility genérica en el futuro, la firma debería aceptar condiciones arbitrarias.

---

### 3.5 `deletion_service.py` vs `cascade_service.py` — responsabilidades solapadas

Dos archivos de "eliminación" en el mismo nivel de servicios. Sin leer los archivos es difícil saber cuál hace qué:

- `cascade_service.py` — claramente maneja cascadas (por entidad, por colección)
- `deletion_service.py` — nombre ambiguo (¿hard delete? ¿complementa el cascade?)

**Recomendación:** Añadir un docstring de módulo que explique la diferencia entre ambos, o considerar fusionarlos si la separación no está justificada por tamaño.

---

### 3.6 `paginate_with_sort` — firma sin tipos estrictos

```python
def paginate_with_sort(
    ...
    order_col=None,      # sin tipo
    order: str = "desc", # acepta cualquier string
):
```

`order: str` acepta `"baz"` sin error. Mejor:

```python
from typing import Literal
order: Literal["asc", "desc"] = "desc"
```
